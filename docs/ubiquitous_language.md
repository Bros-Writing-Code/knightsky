# Shared language Used within the project

## Chess Terms

`Board State`: The physical or spatial arrangement of the pieces across the 64 squares at any exact snapshot in time (who is sitting on which square).

`Game State`:  The complete set of rules and metadata required to know how play proceeds from that board arrangement. This includes whose turn it is, castling rights for both sides, available en passant targets, the half-move clock for the 50-move rule, and move history needed to check for threefold repetition.

`FEN Notation`:

| FEN Component | Value in String | Description |
| :--- | :--- | :--- |
| **Piece Placement** | `rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR` | The board layout, starting from Rank 8 down to Rank 1. |
| **Active Color** | `w` | **White** has the next move. |
| **Castling Rights** | `KQkq` | Both sides can castle Kingside (`K`/`k`) and Queenside (`Q`/`q`). |
| **En Passant** | `-` | No square is available for an en passant capture. |
| **Halfmove Clock** | `0` | Number of moves since the last pawn advance or piece capture. |
| **Fullmove Number**| `1` | The game is currently on move 1. |

## AT Protocol and Identity Terms

- `AT Protocol`: The "Authenticated Transfer" Protocol (pronounced "at protocol", not "Ay Tee"). "Set of open standards for decentralized publishing and distribution of self-authenticating data within the social web" [wikipedia](https://en.wikipedia.org/wiki/AT_Protocol).
- `atproto`: synonymous with `AT Protocol`.
- `Player`: A person in the game (playing as either white or black).
- `Account`: An AT protocol identity.
- `DID`: e.g. `did:plc:...` The permanent ID of an atproto identity.
- `Handle`: e.g. `@alice.bluesky.social`. Human-readable identity term for a DID. The domain of the handle has the DID in a text record, which can be resolved to a PDS. Like the difference between a URL and an IP address. 
- `PDS`: A server that holds repos for atproto identities. Bluesky hosts one for its users, but there are others.
- `Repo`: The total collection of a atproto identity's data on the social web.
- `Record`: Unit of information in an atproto repo. Could be a Bluesky like, a Knightsky game, etc.
- `Session`: The signed-in state the atproto oauth library keeps in IndexedDB
- `AppView`: Bluesky's public index of its social network, used to look up display names after sign in.
- `OAuth`: open standard for access delegation on the web. Used with familiar log in features like the "Sign in with Google" button. Common authentication system for applications that want to allow users to sign in with their atproto identity.

## Lexicon Terms

- `Game record`: The representation of a single chess match between two players. There are two game records per game - one in each player's repo.
- `URI`: Link to an atproto record stored within someone's repo.
- `CID`: Content Identifier. Associated with a record. Changes whenever the record is updated.
- `Strong Ref`: Object type of a lexicon definition that includes a URI and a CID to specify a particular revision of a record.
- `Challenger`: Player that invites another player to play a game of chess.
- `Challenge field`: Optional field of the game record; strong ref to the challenger's original game record.
- `Invitation`: Game records that are generated by the challenger which do not have a `challenge` field.
- `Acceptance`: Game records that are generated by the challenged player include a `challenge` field.
- `Reject record`: The representation of a complaint about an update made by the opponent in a chess game. Offensive updates include things like moving out of turn or making an illegal move. Reject records do not eng the game.
